# Replace hapi-swagger with a build-time generated `openapi.json`

## Why

`hapi-swagger` is archived and unmaintained, and its dependencies (`handlebars`, `swagger-ui-dist`,
`swagger-parser`, `@apidevtools/json-schema-ref-parser`, `http-status`) are periodically flagged by
security scanners. It must go **entirely**, including as a devDependency: scanners flag those too.

Other teams use the Swagger UI the services serve today (`/`, `/swaggerui`, `/swagger.json`), so the
spec itself has to stay available. They only need to **view** it.

## Constraints

- **Joi stays the source of truth** for the unversioned (non-`beta-*`) routes: Joi → validation, Joi →
  spec. Unlike `beta-*`, where JSON Schema → validation and spec. Nothing about Joi validation changes.
- **Same version, format and content as today:** Swagger/OpenAPI **2.0**, exactly what hapi-swagger 17.3.2
  emits. Not converted to 3.1.
- **No drift:** the spec is generated from Joi, and CI fails if the committed copy is stale.
- **Don't call it "legacy"** in names, paths or page titles.
- Applies to both `waste-movement-backend` and `waste-movement-external-api`.

## Design

- **Generator in `waste-movement-utils`** at `src/openapi/`: `generateOpenApi(routes, options)` wraps
  hapi-swagger 17.3.2's Joi→Swagger core, vendored as `.cjs` under `src/openapi/vendor/`
  (MIT licence kept, near-literal copies). Dropped: `index.js` (plugin/UI, handlebars,
  swagger-ui-dist) and `validate.js` (swagger-parser). Replaced locally: `json-schema-ref-parser` with
  `dereference.cjs` (inlines `#/definitions/*` only), and `http-status` with `status-text.cjs`. Not
  re-exported from `src/index.js`, so it's never loaded at runtime; services deep-import
  `@defra/waste-movement-utils/src/openapi/index.js`. `@hapi/hoek` becomes a direct dependency.
- **Each service** commits `src/schemas/openapi.json`, generated by `scripts/generate-openapi.js`
  (`npm run openapi:generate`). The script builds an in-memory `Hapi.server()` with only the `router`
  plugin and `ENVIRONMENT=dev` (full non-prod route set, real CDP host), passes `server.table()` and
  today's swagger options and route-tag filter to `generateOpenApi`, and writes
  `JSON.stringify(spec, null, 2)` plus a newline. `src/schemas/openapi.json` goes in `.prettierignore`.
- **Staleness test** in `src/schemas/openapi.test.js` regenerates the spec in-process and `toEqual`s the
  committed file. In the backend it's a new `describe` beside the existing `beta-*` checks, whose
  discovery is untouched; in the gateway it's a new file.
- **Per-route `plugins['hapi-swagger']` blocks stay**: they're the generator's input for response docs.
- **Publishing**: `digital-waste-tracking-api-docs` syncs both services' `openapi.json` and renders them
  with Swagger UI next to the `beta-*` pages. The services stop serving swagger.

## Steps

### 1. `waste-movement-utils`

- [ ] Before anything else, capture golden snapshots with hapi-swagger 17.3.2 (from a service's
      `node_modules`) for fixture routes and for one route using `receiveMovementRequestSchema`, and
      commit them as JSON under `src/openapi/test-fixtures/`.
- [ ] Copy the hapi-swagger 17.3.2 core into `src/openapi/vendor/*.cjs`: `builder`, `paths`, `properties`,
      `parameters`, `responses`, `definitions`, `utilities`, `filter`, `group`, `sort`, `tags`, `info`.
      Add `vendor/LICENSE` (MIT) and a short `vendor/README.md` recording the upstream version and
      every local edit.
- [ ] Add `vendor/dereference.cjs` (replaces `@apidevtools/json-schema-ref-parser`: inlines local
      `#/definitions/*` refs, matching `deReference: true`) and `vendor/status-text.cjs` (replaces
      `http-status`). Point the vendored `require`s at them.
- [ ] Add `src/openapi/index.js`: `generateOpenApi(routes, options)` → Swagger 2.0 object, applying
      hapi-swagger's defaults and the `routeTag` filter the plugin used to apply.
- [ ] Add `@hapi/hoek` as a direct dependency (it's already in the tree). Respect the 7-day
      release-age policy.
- [ ] Exclude `src/openapi/vendor/` from ESLint, Prettier and coverage.
- [ ] `src/openapi/index.test.js`: fixture routes and the `receiveMovementRequestSchema` route must
      deep-equal the golden snapshots.
- [ ] Update the README with the new export and why it isn't on `src/index.js`. Release a new minor
      version to npm.

### 2. `waste-movement-backend`

- [ ] Bump `@defra/waste-movement-utils` to the new version (`.npmrc` already excludes it from the
      release-age rule).
- [ ] Add `scripts/generate-openapi.js` and the `openapi:generate` npm script. Move the options from
      `src/plugins/swagger.js` into it unchanged (info, tags, `routeTag: 'movements'`, `deReference`,
      sorting, `pathPrefixSize`, `schemes`, host logic run as `dev`).
- [ ] **Acceptance:** with hapi-swagger still registered, the `/swagger.json` it serves as `dev` must
      deep-equal the `generateOpenApi` output. Record the result in the PR description.
- [ ] Generate and commit `src/schemas/openapi.json`, and add it to `.prettierignore`.
- [ ] Add the staleness `describe` to `src/schemas/openapi.test.js` (failure message: "run
      `npm run openapi:generate`").
- [ ] Delete `src/plugins/swagger.js`, unregister Inert, Vision and swagger in `src/server.js`, and
      remove `hapi-swagger`, `@hapi/inert` and `@hapi/vision` from `package.json` and the lockfile.
- [ ] Remove any tests asserting on `/swagger.json` or `/swaggerui`. Update `src/schemas/README.md`
      (the "hapi-swagger is not part of this" paragraph and the "No `tags`, no `hapi-swagger` block"
      note) and `CLAUDE.local.md`.
- [ ] `npm test` and `npm run test:integration`.

### 3. `waste-movement-external-api`

- [ ] Bump utils. The gateway's `.npmrc` doesn't exclude utils, so wait 7 days after release.
- [ ] Same as the backend: `scripts/generate-openapi.js` (`routeTag`: `movements` or
      `production-approval-tests`), the acceptance comparison, a committed `src/schemas/openapi.json`,
      a new `src/schemas/openapi.test.js`, then remove hapi-swagger, inert and vision and
      `src/plugins/swagger.js`.
- [ ] `npm test`.

### 4. `digital-waste-tracking-api-docs`

- [ ] `scripts/sync-schemas.sh`: also copy the backend's root `src/schemas/openapi.json` →
      `docs/event-model/schemas/openapi.json`, and sparse-clone `waste-movement-external-api` to copy its
      `src/schemas/openapi.json` → `docs/event-model/schemas/waste-movement-external-api/openapi.json`
      (with its own `SCHEMA_SOURCE_*`-style override variables).
- [ ] `scripts/bundle-specs.js`: add both to the spec list → `docs/api/openapi-waste-movement-backend.yaml`
      and `docs/api/openapi-waste-movement-external-api.yaml` (gitignored). Check that the validator
      accepts 2.0.
- [ ] Add `docs/api/openapi-waste-movement-external-api.md` ("API spec (Receipt of Waste)") and
      `docs/api/openapi-waste-movement-backend.md` ("API spec (waste-movement-backend, internal)") with
      the internal-doc frontmatter and warning, plus `mkdocs.yml` nav entries. Don't touch the existing
      `openapi.yaml`/`openapi.md`.
- [ ] Update `CLAUDE.local.md` and README.

### 5. Rollout

Order: utils release → services commit `openapi.json` (hapi-swagger still present; acceptance passes)
→ api-docs publishes the new pages → tell the consuming teams the new URL → services remove
hapi-swagger.

## Out of scope

- Converting the unversioned API's spec to OpenAPI 3.1 or JSON Schema.
- Changing Joi validation, route paths or the `beta-*` mechanism.
- Documenting routes hapi-swagger doesn't document today (e.g. the gateway's `reference-data` GETs,
  which are tagged `reference-data` and so excluded by `routeTag`).
